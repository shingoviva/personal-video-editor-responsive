# PVE Product Vision

> 開発時点の記録です。2.2.84の最新の採否・制約・公開状態は[リリース報告](PVE-2.2.84-RELEASE-REPORT.md)を参照してください。


基準日：2026-10-23。今後の判断基準。現行機能の実装済み一覧・品質保証ではありません。

## 完成目標

個人制作による本格的な動画編集ソフトとして、プロのアーティストのMV、ファッションフィルム、ブランドのプロモーション映像を、特殊なVFX制作を除き、PVEで編集・仕上げ・高品質に書き出し、実際に納品できる状態を目指します。

Premiere ProやDaVinci Resolveの全機能の再現は目指しません。熟練した個人ユーザーが、必要な機能を深く、素早く、安定して使えることを優先します。既存のPhotographer-firstは映像を見る感覚として継承し、本格的な編集・仕上げの完成目標へ広げます。

## 操作の原則

- タイムラインとプレビューを編集の中心にし、意図を少ない操作で反映します。
- 各機能の主要な操作場所を一つに定め、関連設定を集約します。同じ目的の独立した設定画面は増やしません。
- タイムライン上の直接操作、コンテキストメニュー、ショートカットは有効な別入口です。同じ状態・コマンド・Undoへ接続します。
- 数値入力と直接操作を同じ対象へ反映し、選択対象、時間基準、適用範囲、変更後の尺を予測できるようにします。
- 不必要なモーダル、画面遷移、スクロール、適用ボタンを減らします。詳細設定は中心の編集作業へ戻りやすくします。
- シーク、ドラッグ、再生、パラメータ変更の反応を優先します。計算の軽量化だけで操作改善を断定しません。
- Macはマウスとキーボード、iPhoneはタッチと限られた表示領域に最適化します。意味・状態・結果は共通にします。
- 初心者向けの機能削減より、熟練した個人ユーザーの作業効率を重視します。AI解析は候補提示とし、自動確定しません。

## 品質基準と完成判定

以下は今後の受入基準です。現時点で全項目の達成を確認したものではありません。

| 領域 | 受入基準・証拠 |
|---|---|
| 保存・復元 | 保存失敗や容量不足でも、既存の素材コピーと直前の有効なプロジェクトを保持。保存→再起動→復元、再リンク、失敗注入で確認 |
| 編集の正確性 | 移動・分割・トリム・速度・Undo/Redo・保存復元で、意図したフレームと音量形状を保持。プロジェクトの時間基準を明示し、吸着とフレーム量子化を区別 |
| プレビュー・シーク | 再生開始、連続シーク、逆方向シーク、重なり・末尾で古いフレームや音声を残さない。プレビューと出力の意図的な品質差を説明できる |
| 色・合成 | 同じテスト素材で色、アルファ、テキスト、FX順序を比較。SDR/HDR、近似表示、処理プレビュー、出力の差を記録。ブラウザとMacの完全一致は未保証 |
| 音声同期 | 再生・シーク・速度変更・分離/連動・分割境界で同期を維持。PCM差分と音画マーカーで計測し、実聴を併用 |
| 書き出し | 指定の解像度、fps、比率、尺、音声、コーデック、ファイル名を保持。全尺デコード、フレーム/音声境界、メタデータ、再生互換性を確認 |
| 性能 | 同一素材・端末・viewport/DPR・出力条件でbefore/afterを測定。シーク/入力遅延p50/p95、フレーム締切超過、音声ドリフト、メモリ、出力時間を記録 |
| 実務納品 | 許諾済みのMV・ファッション・ブランド各代表案件で、素材読込→編集→色/音→保存復元→出力→独立再生まで通し、制作者本人が画と音を承認 |

数値目標は各実装課題の開始時に基準測定とともに定めます。フレーム精度は採用した時間基準に対して検証し、近似の許容誤差や端末差を黙って広げません。iPhone 16 Pro・M2 Macを優先し、実機Safari・HDR実写・長時間・実聴の未確認を合格と記載しません。

## 互換性とデータ保護

現利用者は開発者本人のみです。UI再配置、機能統合、フロー改善、内部整理、保存形式改訂、不要な旧実装の段階的廃止を許容します。旧配置・実装方式・全旧形式の完全互換を絶対条件にしません。

保存済みプロジェクトと素材は無断で削除・破壊しません。互換性を破る実装に入る前に、対象形式・失われる情報・復旧方法を説明し、別名バックアップまたは安全な移行経路を用意します。移行はコピーへ行い、失敗時は旧データで再開できることを確認します。旧機能の撤去は参照状況と代替手段を確認して個別に判断します。

現行AGENTSの旧設定保持などは、安全な移行が整うまでの実装上の保護です。改訂を永久に禁止するものではありません。既存の映像3段・音声4段等は現行基準であり、完成目標の上限とはしません。

## 開発の進め方

保存の安全性と正確性を先行し、操作整理、Speed統合、手ぶれ補正研究、計測に基づく性能改善を小さく進めます。WebGPU移行は現段階では行いません。一作業に複数の巨大な機能変更を混在させません。

長い調査はファイルへ残し、AGENTSは短い入口に留めます。必要ファイルを段階的に読み、局所試験を優先します。既存の完了時test/build規則と正式公開前の全回帰を維持します。今回の調査は未公開・バージョン更新なしです。

具体的な現状は[UX棚卸し](PVE-UX-INVENTORY.md)、優先順位と完了条件は[ロードマップ](PVE-ROADMAP.md)を参照します。READMEは現行仕様、VALIDATIONは検証記録として併用し、過去のリリース記述を将来方針より優先しません。
