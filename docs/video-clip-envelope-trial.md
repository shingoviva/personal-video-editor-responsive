# 動画クリップ内の音量ライン：未公開試作

## 両端・水平ラインの追補（未公開）

動画/音声共通で始点・終点のハンドルを表示します。両端は正確に0秒/クリップ尺へ固定し、上下ドラッグでフェードを作れます。未編集の両端は表示補助のみで、触って編集した時に既存のgainEnvelope形式の点へ確定します。途中のポイントを打たなくても水平ラインを上下ドラッグでき、その場合は両端を同じ値にして水平を保ちます。既存の基本音量・フェード・DSP・保存形式は変更しません。

水平なラインの横ドラッグは、同じpointerを既存のクリップ移動処理へ渡します。縦方向の小さな揺れだけでは変更しません。トリムのつまみは上部へ、端点ノブは下部のグラフへ分けています。最小音量の線が段の高さ調整ハンドルに隠れないよう、グラフ下部に6 CSS pxを予約。低いグラフでも0 dBへの吸着がプラス側の全域を覆わないよう上限を設けています。通常高さの既存の吸着試験は維持しています。

タッチでライン自体を取得する場合もダブルタップを認識し、互換mouse dblclickで二重処理しません。最大256点の制約では既存点を勝手に削除せず案内します。境界補助点の確定前後で、既存hold/linear曲線の1,601時点が数値完全一致しました。

Mac Chrome、スマホChromeのネイティブCDP touch、スマホWebKitのmouse drag＋ネイティブtouchscreen double tapで、動画/音声双方の水平上下・横移動・UndoRedo・中間点追加・端点固定・fade・上部トリムを確認。8秒クリップの両端が厳密に0秒/8秒に留まり、内部点を保ったまま両端を-96 dBへ下げられます。全89 JS試験、build、既存preview操作回帰、英語案内の収まりもPASS。実機iPhone/Safari、実聴音/新しいPCM比較は未確認です。

## 表示と操作

- 動画の上部を素材名と速度/長さの細いヘッダーにし、下部を原音の音量ライン専用にしました。明るいサムネイルでも見えるようグラフ背景を暗くしています。
- 短いクリップは速度/長さを省略し、素材名とグラフを優先。段の高さを変えても名前/尺/曲線は重なりません。
- 音声クリップと同じく、ラインのダブルクリック/ダブルタップでポイントを追加。点を上下/左右にドラッグし、0 dB吸着、MacのShift微調整、右クリックの直線/一定/削除に既存の共通処理を使います。点選択後のDeleteは動画本体を消しません。
- 標準の低い段では大きな音量変化は操作できますが、細かい調整は段を広げるか、音声タブの音量ポイント数値入力を使う方が確実です。音量カーブは基本音量・ミュート・フェードとは別に適用される既存の仕様を維持します。
- 静止画・空白・静止フレーム・音声なし素材・原音分離済みの動画には表示しません。分離時はポイントを保った音声クリップ側にグラフが移ります。動画では新しい波形解析を行いません。

## 検証と限定した修正

Mac Chrome1440×900、WebKitスマホ393×852で、名前/尺/グラフの領域分離、ポイント追加・移動を確認。MacはUndo/Redo、ポイントだけのDelete、V1→V2移動、トリム、狭幅の省略、段の拡大/標準復帰、分離後のポイント保持も確認しました。スマホはダブルタップを実際に入力しましたが、ポイントドラッグは合成pointerイベント（capture stubあり）で、実機の指操作と同一とは報告しません。

単純なクリップ選択でDOMが作り直され、native double-clickの途中で対象が変わる問題を検出しました。動画/音声の「位置も長さも変わらない選択」だけ `render({preserveTimeline:true})` を使い、編集/Undo/読み込み等の通常renderは従来どおり再構築します。選択用分岐を他の編集へ安易に流用しないでください。既存音声も同じpoint bindingへまとめ、保存/描画/波形解析の処理自体は維持しています。

全89件のnpm test、npm run build、git diff --check成功。既存Chrome操作試験も、素材配置/右クリック/再生中seek/ドラッグ/loop/Shift/preview停止解除を含めて成功。新しい回帰は動画の対象条件、波形UI非生成、選択時のDOM維持と通常renderの再構築を検証します。
